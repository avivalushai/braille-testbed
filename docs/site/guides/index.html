Guides

  • Sync a folder to a bucket — The common first job: watch a folder, copy new files to object storage, keep the names
  • Copy a table to a warehouse — Read a table in pages, write it in batches, and keep a cursor so the next run continues
  • Two-way syncs — Two-way syncs need a conflict rule, and a field that says when a record last changed
  • Filtering records — Filters run before the transfer, so a filtered record costs nothing but the read
  • Keeping credentials out of the file — Reference an environment variable or a secrets manager; never write a credential into kestrel
  • Watching a sync in production — Alert on runs that did not start, not just runs that failed: a sync that never ran is the one nobody notices
  • Large files — Above the multipart threshold, Kestrel splits a file and retries only the parts that fail
